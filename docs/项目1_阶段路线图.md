# 项目① 诚实回测：XAUUSD MACD 面积背驰 —— 阶段路线图

## 项目定位

用自己写的 Python 代码，对 XAUUSD 的 MACD 面积背驰策略做一个**可控、可审计**的回测，输出收益 / 最大回撤 / 夏普，主动避开未来函数和过拟合两大陷阱，并与 TradingView 结果对比。

- 信号选择：MACD 面积背驰（从缠论中拆出最核心的背驰判断，单独验证）
- 骨架验证：先用 MACD 金叉死叉跑通全部五层，再把信号层升级为面积背驰

## 通用原则

- **过关标准统一是"关掉 AI 也能做到"**：每个阶段结束时，不借助 AI 改一个参数、加一个功能，或把代码讲给别人听。做不到就在本阶段多停一周。
- **能解释每一行**：任何代码合并进项目前，必须能说清楚它每一行在做什么。
- **AI 的角色是教练，不是代写**：先解释再动手；给提示不给答案；让它出题考你；自己写完再让它审。
- **阶段顺序不跳**：时间可按课程和工作情况伸缩，但顺序保持不变。

## 项目结构

```
xauusd-macd-backtest/
├── data/                 原始与清洗后的 K 线
├── docs/                 规则说明、数据说明
├── notebooks/            逐层检查用的 notebook
├── reports/              自动生成的图表与报告
├── src/
│   ├── data_loader.py    数据层
│   ├── indicators.py     指标计算（MACD）
│   ├── signals.py        信号层（金叉死叉 / 面积背驰）
│   ├── executor.py       执行层（成交、点差、止损）
│   ├── metrics.py        评估层（收益、回撤、夏普）
│   └── report.py         报告层（画图、导出）
├── tests/                测试（含防未来函数测试）
├── config.yaml           所有参数
├── main.py               总开关，按顺序调用各层
└── README.md             中文设计思路
```

## 阶段 0：搭环境、写规则（约 1 周）

**要做的事**
- 安装 Python 环境，建立项目文件夹，初始化 git 并推送到 GitHub
- 把策略规则写成中文说明，至少覆盖以下六点：
  1. 怎么切段（MACD 柱子从过零到下一次过零为一段）
  2. 拿哪两段比（当前同向段 vs 上一个同向段）
  3. 背驰判定条件（价格创新高/新低 + 面积缩小；是否设比例门槛）
  4. 信号确认时点（柱子翻转那根 K 线收盘确认，下一根开盘入场）
  5. 出场规则（止损位置、止盈方式、是否有时间止损）
  6. 参数与周期（MACD 12/26/9，固定周期如 1 小时，第一版不调参）

**交付物**
- GitHub 上的项目骨架（文件夹结构 + 空的 `.py` 文件）
- `docs/strategy_rules.md`：金叉死叉与面积背驰两套规则说明 v1

**过关标准**
- 能自己 commit 和 push
- 规则说明里每一条都能回答"代码里具体怎么判断"

## 阶段 1：数据层（约 2–3 周，同时学 pandas）

**要做的事**
- 从 Dukascopy 下载 XAUUSD 1 小时数据
- 处理时区、周末断档、缺失 K 线、异常跳价

**交付物**
- `src/data_loader.py`：输入日期范围，输出干净的 K 线表
- `notebooks/01_data_check.ipynb`：数据检查记录（画图、缺失统计）
- `docs/data_notes.md`：数据来源与清洗规则说明

**过关标准**
- 能讲清楚每一步清洗为什么要做
- 能自己修改日期范围并重新生成数据

---

## 阶段 2：指标层（约 1–2 周）

**要做的事**
- 自己实现 MACD 计算（DIF、DEA、柱子）
- 画出 K 线 + MACD 副图

**交付物**
- `src/indicators.py`
- 对比截图：自己算的 MACD 数值 vs TradingView 同一根 K 线的数值

**过关标准**
- 数值与 TradingView 对得上；若有微小差异，能解释原因

---

## 阶段 3：用金叉死叉跑通完整骨架（约 3–4 周）⭐ 最关键

**要做的事**
- 用 MACD 金叉做多、死叉做空，写出执行层、评估层、报告层
- 用 `main.py` 把五层串起来

**交付物**
- `src/executor.py`：下一根 K 线开盘入场、扣点差、止损
- `src/metrics.py`：收益、最大回撤、夏普、胜率、盈亏比
- `src/report.py` + `config.yaml` + `main.py`
- `reports/` 下第一份完整回测报告（权益曲线、回撤图、逐笔交易清单）

**过关标准**
- 从交易清单随机挑 5 笔，手动核对入场价、出场价、盈亏全部正确
- 自己修改点差参数并重跑

> 骨架对了，后面换任何策略都只需改信号层。项目②的流水线也建在这个骨架上。

---

## 阶段 4：面积背驰信号（约 2–3 周）

**要做的事**
- 实现切段、计算面积、判断背驰、确认信号时点
- 替换掉金叉死叉信号

**交付物**
- `src/signals.py`
- 可视化检查图：K 线图上标出每个 MACD 段的面积和背驰信号，与 TradingView 对照
- `tests/test_no_lookahead.py`：防未来函数测试
  - 思路：只用截至某一时刻的数据算出的信号，必须与用全部数据算出的同一时刻信号完全一致；不一致即说明偷看了未来

**过关标准**
- 防未来函数测试通过
- 随机挑几个信号，能在图上指出它为什么被判定为背驰

---

## 阶段 5：诚实评估（约 2 周）

**要做的事**
- 划分样本内 / 样本外；样本外数据在最终测试前不看、不调参
- 点差敏感性测试：点差加倍后策略是否仍然盈利
- 与基准对比：同期买入持有黄金、随机入场
- 与 TradingView 同规则回测结果对比，解释差异来源

**交付物**
- `reports/final_report.md`：包含以上全部对比结果

**过关标准**
- 结果无论好坏都如实呈现，并能解释原因
- 策略不赚钱也完全没问题——"诚实地证明它不行"本身就是项目意义

---

## 阶段 6：包装发布（约 1 周）

**要做的事**
- 撰写中文 README，整理代码与注释

**交付物**
- README 包含：
  - 项目动机（从缠论拆出背驰单独验证）
  - 系统架构图
  - 策略规则
  - 如何避开两大陷阱（未来函数、过拟合）
  - 回测结果与局限性
  - 如何运行

**过关标准**
- 一个不认识你的人能照着 README 跑起来，并看懂你在做什么
